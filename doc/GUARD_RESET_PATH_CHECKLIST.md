# 가드 리셋 경로 점검 체크리스트 (2026-08-03)

> 누적 상태에 의존하는 가드는, 그 상태를 리셋하는 경로가 **병리 조건이 지속되는
> 동안에도** 발생할 수 있으면 무력화된다. EDIE와 SW2가 서로 모르는 채 같은 버그
> 계보를 반복한 것이 실증 근거다(아래 사례). 새 가드를 설계하거나 기존 가드를
> 리뷰할 때 이 체크리스트를 적용한다.

## 문제 정의

가드의 전형적 구조는 "누적 상태가 문턱을 넘으면 개입"이다. 여기서 누적 상태란
카운터(연속 발동 횟수), 비율(제거율·정화율), streak(연속 무이상), 앵커(기준
위치·기준선), 쿨다운(재발화 억제 시각) 등이다. 이 상태들은 어딘가에서 리셋된다 —
명시적 초기화, 재기동, 저장소 소멸, 분모 재계산. **리셋 자체는 정상 동작이지만,
리셋 조건이 병리 조건과 독립이 아니면 병리가 리셋을 유발해 가드를 영구 회피한다.**

## 실증 사례 (버그 3건 + 예방 성공 1건)

### 사례 1 — EDIE `179807f`: 자기참조 리셋 (2026-07)

4선 에스컬레이션 가드는 "정화(무이상 solve) 없는 연속 절제 3회 → 조기 재초기화"인데,
초기 구현은 정화 판정에 cum_hit(누적 변위 가드 발동)를 포함했다. 누적 가드가 환원을
수행하는 중의 solve는 주행 문턱 아래로 내려가 '무이상'으로 오판되고, **에스컬레이션
카운터가 리셋**된다. 결과: 중간 강도 폭주가 4선을 영구 회피할 수 있었다.
수정 = 정화 판정에서 cum_hit 제외.

**패턴: 리셋 트리거(정화 판정)가 가드 자신의 발동 부산물(cum_hit로 인한 환원)에
오염 — 자기참조 루프.**

### 사례 2 — SW2 lifelong 3.67: 세션 경계 비영속 (2026-07)

노드 은퇴 가드의 조건 "제거율 ≥ 50%"는 "원래 희박한 노드"(보호 대상)와 "사멸로
빈 노드"(배제 대상)를 구분하려는 것이다. 그런데 삭제된 특징은 재기동 시 DB에서
로드 자체가 안 되어 `removed` 배열이 전부 False로 초기화된다 — **제거율이 세션마다
0으로 리셋**된다. 지난 세션에 60%를 비운 노드가 원래 희박한 노드로 위장되어,
가드가 걸러내려던 대상과 보호하려던 대상이 뒤섞인다. 은퇴 4조건 중 잔존 word 수는
이미 세션 간 누적인데 제거율만 비대칭이었다 — 의도된 보수성이 아니라 누락.
수정 = 아카이브 테이블을 분모·분자에 합산해 세션 간 누적으로 전환(13줄 diff).

**패턴: 세션/재기동 경계에서 상태가 영속되지 않아, 가드의 의미가 "누적 조건"에서
"세션 내 조건"으로 몰래 변질.**

### 사례 3 — SW2 lifelong 3.64: 저장소 수명 < 상태 수명 (2026-07)

구역 쿨다운(600s)이 Khronos 객체 레코드 안에 저장돼 있었다. 객체가 변화감지 한
라운드에서 안 보이면 신선도 규칙이 레코드를 pop하는데, **쿨다운이 레코드째
증발**한다. 결과: 600s 쿨다운인데 같은 구역이 15s 간격으로 4회 중복 발화.
커버리지 경로는 복셀(공간) 키 쿨다운이라 면역 — 객체 경로만 취약.

**패턴: 상태를 담은 엔티티의 수명이 상태의 의도 수명보다 짧다. 시간 의미의 상태를
소멸 가능한 객체에 매달면 안 된다.**

### 사례 4 (예방 성공) — EDIE z 래칫 가드의 앵커 계승 (2026-07-31)

정지 창 재진입마다 앵커를 새로 잡으면(재래치) 다리 이벤트가 만든 z 계단이 새 앵커에
구워져 래칫을 지울 수 없게 된다 — 앵커 리셋이 병리(z 계단)를 합법화하는 구조.
처방 = 앵커 '계승': 리셋(신규 앵커)을 병리와 독립적인 조건(휠 병진 없음 + 다리각
2-LSB 복귀, xy는 추가로 gyro 순적분 <5°)으로 게이팅하고, 조건 미충족 시 이전 앵커를
계승한다. **이 클래스의 버그를 설계 단계에서 차단한 사례** — 체크리스트 Q3·Q4를
사실상 선취 적용한 것.

## 체크리스트

가드 설계·리뷰 시 순서대로 답한다:

- **Q1. 누적 상태 전수 나열** — 이 가드가 의존하는 누적 상태를 전부 나열했는가?
  (카운터 / 비율 / streak / 앵커 / 기준선 / 쿨다운 / 래치 플래그)
- **Q2. 리셋·소멸 경로 전수 나열** — 각 상태에 대해 누가·언제 그것을 0으로
  만들거나 재계산하는가?
  - 명시적 리셋 코드 (`streak = 0`, `clearState()`)
  - 재기동·재초기화·세션 경계 (메모리 상태 소실, DB 리로드)
  - 저장소 소멸 (레코드 pop, 맵 erase, 노드 소멸)
  - 분모·기준의 재계산 (비율의 분모가 바뀌면 사실상 리셋)
- **Q3. 병리 중 리셋 가능성** — 각 리셋 경로에 대해: 가드가 막으려는 병리 조건이
  **지속되는 동안에도** 그 리셋이 발생할 수 있는가? 가능하다면 그것이 곧 가드
  회피 경로다. (사례 1·2·3 전부 여기서 걸린다)
- **Q4. 리셋 트리거의 독립성** — 리셋 조건이 가드가 감시하는 신호, 또는 가드
  발동의 부산물과 독립인가? 가드 개입이 리셋 조건을 만족시키면 자기참조 루프다.
  (사례 1: 환원 중 solve가 '정화'로 보임 / 사례 4: 계승 조건을 외부 센서
  합의로만 구성해 독립성 확보)
- **Q5. 세션 경계 영속성** — 상태가 세션·재기동을 넘어 누적돼야 의미가 있다면
  실제로 영속되는가? 영속 안 된다면 가드는 "세션 내 조건"으로 의미가 바뀌는데,
  그것이 의도인가? (사례 2)
- **Q6. 저장소 수명** — 상태를 담은 엔티티의 수명이 상태의 의도 수명 이상인가?
  시간·공간 의미의 상태는 시간·공간 키에 저장하고, 소멸 가능한 객체 레코드에
  매달지 않는다. (사례 3)
- **Q7. 최악 조합 회귀 테스트** — "병리 지속 + 리셋 발생"의 최악 시나리오를
  gtest로 고정했는가? 정상 경로 테스트만으로는 이 클래스가 안 잡힌다 —
  사례 1은 리뷰 재검증("논리 확실?")에서, 사례 2는 별도 실험(3.66)에서야 발견됐다.
