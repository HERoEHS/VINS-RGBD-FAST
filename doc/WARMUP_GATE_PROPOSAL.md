## 1. 목표

VINS의 초기화(static init)가 **"몸이 실제로 정지·정착했음이 실증되고, 충분한 관측이
쌓인 뒤에만"** 수행되도록 게이팅한다. 부팅·재초기화 직후의 오염된 초기 상태(자세·bias)가
세션 전체 오차의 씨앗이 되는 것을 원천 차단한다.

## 2. 배경 — 실증된 문제 3건

|---|------|------|
| ⓐ | **재초기화가 다리 애니메이션 중 착지** | 07-31 실기: 에스컬레이션 reboot 직후 init의 acc 평균 (1.06, 1.75, 9.43) = 흔들리는 몸의 중력 평균 → R0에 ~10° tilt 구움, zpw 0.094→0.136 오염, 직후 비강체 절제·0.154m 슬라이드 연쇄 |

| ⓒ | 초기 접근 구간 y 벌어짐 | ⓑ의 결과 — heading 3° = 1m 병진당 y 5cm |

## 3. 선례 (검증된 패턴)

- **SW2 reanchor 기준선**: "상태가 실제로 바뀌었음의 실증(map→odom 2cm/0.01rad 이동)
  + 최소 지연" 이중 요건 — 이벤트 발생이 아니라 상태 변화 실증이 조건
- **ALICE 상태추정기 init**: 양발 접지 **1s 연속 유지**(상태 실증) → **IMU 100샘플
  수집**(관측량 조건) → init. 시간 상수가 아니라 "상태 유지 + 표본 수"가 게이트

## 4. 요구사항

- **R1 (핵심)**: static init 창 수집을 다음 조건 충족까지 지연 —
  "휠 정지(v·w 문턱) **AND** 다리각 안정(2-LSB 격자 기준) **연속 실증** **AND**
  IMU 표본 N개 축적". 전부 상태·표본 조건, 시간 상수 금지
  ([[feedback-no-bag-biased-time-constants]] 원칙).
- **R2 (필수 — "확실해?" 2차 수색에서 확정된 요건)**: **운용 중 재초기화 폴백**.
  에스컬레이션 reboot 순간 로봇이 계속 주행 명령을 받고 있으면 R1이 영원히 미충족
  → VINS 출력 공백 무한 연장. 폴백 후보(설계 시 택1):
  ① 저신뢰 init(가드 강화 상태로 잠정 시작, 정지 도래 시 재정렬)
  ② nav에 일시정지 요청(제품 계층 협조 — 아래 R3와 연동)
  **무한 대기 금지가 하드 요건.**
- **R3 (관할 명시)**: "이동 명령 수용 게이트"(부팅 애니메이션 동안 cmd 거부)는
  제품/nav 계층 코드 — VINS 단독 불가. 협조 요청으로 분리 문서화.
- **R4 (재사용)**: 관측 수렴 판정은 기존 bgz_rest 중앙값 기계·정지 3중 검사
  (휠+gyro+다리 게이트)를 재사용한다. 새 판정기를 만들지 않는다.
- **R5 (리셋 경로)**: 게이트 상태는 [GUARD_RESET_PATH_CHECKLIST.md](GUARD_RESET_PATH_CHECKLIST.md)
  Q1~Q7 대입을 설계 단계에서 수행(특히 Q3: 병리 중 clearState가 게이트를 우회하는지).

## 5. 검증 계획

1. **gtest**: 게이트 순수 로직(상태 실증·표본 카운트·폴백 전이) 단위 검증
2. **v13 재생**(무휴식 시작 bag 실물): ~~"이 bag은 정지가 안 옴"~~ **08-03 실측 정정** —
   bag 시작에 4.93s 정지 창 존재(첫 휠 구동 4.94s), 이후에도 ≥2s 정지 구간 19개.
   ALICE급 파라미터(실증 1s+표본 1s)면 게이트는 ~2s에 READY = v13에서 사실상 투명
   → 게이트 '지연'만으로는 ⓑ 개선 없음(**무해성 검증용**으로 강등). **대신 설계 승격
   항목**: 2단 수집 창의 정지 실측 gyro 중앙값은 bias의 직접 물리 관측이므로(4.93s면
   측정 충분 — BGZ-LOCK이 56s에야 발동한 건 관측 불가가 아니라 '최적화 후 안정 창'
   잠금 요건 탓, 53.28s 정지 창 5.05s와 발동 시각 정합) 이를 **init Bg 시딩**에 쓰면
   ⓑ를 직접 처방할 수 있다(R4의 bgz_lock::RestBias 재사용, 배선 설계 결정 항목).
   R2 폴백 경로는 파라미터를 초기 창(4.93s)보다 크게 잡은 인위 조건으로만 발동 가능 —
   자연 검증은 3번(ⓐ bag)이 정본.
3. **재초기화 시나리오**: 에스컬레이션 유발 bag(ⓐ 정지+다리 5분 — 미확보, 별도 대기)
   재생으로 reboot 후 init 품질(R0 tilt·zpw) 전후 비교
4. **실기**: 부팅 즉시 출발 시나리오 A/B

## 6. 리스크

- init 지연 = VINS 출력 공백 연장 — R2 폴백이 상한을 보장해야 함(핵심 트레이드오프)
- 다리각 "안정" 판정과 애니메이션 유휴 동작의 상호작용(대기 중에도 미세 애니메이션이
  돌면 게이트가 안 열림) — 제품 애니메이션 정책 확인 필요(R3 협조 항목)
